# Flisk Restaurant Operations Demo Guide

## Run the Project

From the project root:

```bash
cd flisk-restaurant-example
```

Make sure Docker/Colima is running before using Tilt-managed containers:

```bash
colima start
docker info
```

Regenerate the Flisk project output after changing `.flisk/project.json`, `service.json`, or Flisk CLI generation code:

```bash
flisk project --yes
```

Start the full restaurant landscape:

```bash
flisk up
```

Or start one domain stack:

```bash
flisk up guest
flisk up kitchen
flisk up operations
```

Flisk discovers six resources from `service.json` manifests across the `guest`, `kitchen`, and `operations` stacks.

## Local Browser URLs

When the local HTTP bridge or Traefik proxy is running, use these URLs:

```text
Reservation app: http://reservation-app.app.flisk-restaurant-example.localhost/
Floor app:       http://floor-app.app.flisk-restaurant-example.localhost/

Guest API:       http://api.flisk-restaurant-example.localhost/api/guest-management
Kitchen API:     http://api.flisk-restaurant-example.localhost/api/kitchen-management
Operations API:  http://api.flisk-restaurant-example.localhost/api/operations-management
```

Direct service ports are:

```text
reservation-api   http://localhost:4100/health
reservation-app   http://localhost:3100
kitchen-api       http://localhost:4110/health
kitchen-worker    http://localhost:4111/health
menu-api          http://localhost:4120/health
floor-app         http://localhost:3120
```

## Direct Dev Server Fallback

If Docker/Tilt is not available, run the services directly with Bun/Vite:

```bash
(cd services/guest/reservation-api && bun run dev)
(cd services/guest/reservation-app && bun run dev)
(cd services/kitchen/kitchen-api && bun run dev)
(cd services/kitchen/kitchen-worker && bun run dev)
(cd services/operations/menu-api && bun run dev)
(cd services/operations/floor-app && bun run dev)
```

Each command runs a foreground process. Use separate terminals, or run only the resources needed for the demo.

## Three-Minute Walkthrough

### 1. Start the landscape

```bash
flisk up
```

Show that Flisk discovers the six restaurant resources and generates `.autogenerated/` files for each resource.

### 2. Inspect guest service boundaries

Open `services/guest/reservation-api/service.json` and point out the PSR contract: `appName`, `domain`, `appType`, `stack`, `port`, dependencies, and health check.

### 3. Move through the restaurant

- Guest: reservation intake, waitlist, and table hold status.
- Kitchen: active tickets and station pacing.
- Operations: menu availability and floor visibility.

### 4. Start one stack

```bash
flisk up kitchen
```

Use this to show how an individual restaurant domain can run without booting every resource.

### 5. Extend the example

```bash
flisk resource payments-api --type backend --stack operations
flisk stack operations
flisk up operations
```

The new service follows the same manifest-driven workflow as the existing restaurant resources.
